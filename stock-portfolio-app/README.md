# 나의 주식 포트폴리오 (MVP)

가족/지인이 함께 쓰는 개인용 데스크톱 주식 포트폴리오 프로그램. 현재 구현된 기능:

- **홈 대시보드**: 토스증권/네이버증권 홈 화면을 참고해서 앱을 열면 가장 먼저 보이는 요약 화면. 총 자산(통화가 섞이면 환율로 환산해서 큰 숫자 하나로), 매입원가 대비 누적 평가손익(금액+%), 최근 스냅샷 추이 미니 그래프, 보유 비중 상위 종목(클릭하면 종목 상세로), 다가오는 적립식 회차, 이번 달 배당, 다른 탭으로 바로 이동하는 바로가기 타일로 구성됨 — 새 계산 로직 없이 기존 페이지들의 계산을 재사용해서 요약만 보여줌
- **재무 정보 & 목표**: 주식 외 자산/부채(월급 등 소득, 적금/예금, 대출)를 등록하면 순자산(주식 평가금액 + 예적금 − 대출)과 월 투자 가능액(소득 − 적금 납입액 − 대출 상환액)을 자동 계산함. "45세 전 20억 모으기" 같은 목표를 금액+목표일(또는 현재 나이/목표 나이로 자동 계산)로 등록하면, 지금 순자산·월 투자 가능액·가정 수익률로 목표일에 도달할 것으로 예상되는 금액과 달성 가능 여부, 부족하면 목표를 맞추려면 필요한 월 투자액을 계산해서 보여줌(`domain/financialGoal.ts` — 기존 복리 계산 엔진(`compound.ts`)을 그대로 재사용). AI(LLM) API 연동은 비용·개인 재무 데이터의 외부 전송 문제로 이번엔 보류하고, 전부 로컬 계산으로만 구현함
- **보유 종목** 수동 입력 (증권사별 그룹핑). 평가손익에 금액과 함께 **수익률(%)**도 같이 표시함(토스/네이버 증권 관례)
- **적립식 계획**: 종목별 계획 등록 + 예정 회차 자동 생성 (실제 매수는 사용자가 직접 진행). 주기는 **매월/매주/매일(영업일 기준, 주말 제외)** 중 선택 가능하고, 회당 적립을 **금액**(예: 30만원)으로 할지 **수량**(예: 0.5주, 소수점 매수 지원)으로 할지도 선택 가능 — 수량 기준이면 가정 수익률만큼 주가도 같이 오른다고 보고 회당 투입 금액이 매달 재계산됨(`projectQuantityContributionGrowth`). WEEKLY는 한 달 평균 4.348번(365.2425/7/12), DAILY는 영업일만 쳐서 한 달 평균 21.74번(30.44일×5/7, 공휴일은 미반영)으로 월 환산해서 계산함(`monthlyEquivalentMultiplier`). **"다음 예정 매수 회차"는 시작일이 훨씬 과거여도(이미 몇 달 전부터 모아온 종목) 오늘 이후 회차만 정확히 보여줌**(`nextScheduledEvents`) — 예전엔 시작일부터 순서대로 나열해서 이미 지난 회차가 "다음 예정"으로 잘못 나왔었음. 계획을 선택하면 시뮬레이션 그래프도 **적립 시작일(계획에 적어둔 startDate)부터 오늘까지 실제 시세로 복원한 "실제 평가금액(과거)" + 그 지점에서 이어지는 "예상 평가금액/납입원금(향후)"**을 하나의 날짜 축으로 이어서 보여줌(`compound.ts`의 `initialValue` — 미래 시뮬레이션이 투입원금이 아니라 실제 현재 평가금액에서 시작하도록 분리). 적립 시작일이 종목 등록일보다 빠르면(과거부터 모아온 종목을 나중에 등록한 경우) 그 사이 구간은 등록 시점 수량을 시작일부터 그대로 갖고 있었다고 가정한 추정치임을 화면에 안내함. 계획을 선택하면 **종목 자체 등락률**(적립 시작일 종가 대비 최근 종가, 내 매수 타이밍과 무관한 순수 주가 성과)도 함께 표시함
- **다통화(KRW/USD) 안전장치**: 적립식 계획·포트폴리오 합산·배당 시뮬레이션 전부 통화를 섞어서 더하지 않고 기본적으로 통화별로 분리해서 계산·표시함 — 화면에 찍히는 숫자에는 항상 실제 통화가 붙어서(`formatMoney`), 달러 종목 금액이 "원"으로 잘못 표시되는 일이 없음
- **환율/시장지수**: 상단에 코스피·코스닥·다우·나스닥·S&P500 등 주요 지수와 원/달러 등 환율이 흐르는 티커바 표시(5분마다 자동 갱신, 네이버 금융 공개 데이터). 보유 종목/종목 상세/적립식 계획/포트폴리오 합산/배당 페이지 전부 "원화로 환산해서 보기(또는 전체 하나로 합쳐 보기)" 토글로 실시간 환율 기준 원화 환산·합산 가능 — 어디까지나 표시용 환산이고 실제 저장 데이터는 원래 통화 그대로 유지됨
- **적립식 계획 — 원화로 입력 & 전체 합산**: 해외(USD) 종목을 '금액' 방식으로 적립할 때 토스증권처럼 "원화로 얼마어치 살지"를 직접 입력할 수 있음(입력 통화 토글, 저장 직전에 그 시점 환율로 달러로 환산해서 저장 — 저장 데이터 자체는 항상 원래 통화 기준). 적립식 계획 탭 안에서도 활성 계획 전체를 통화 상관없이 원화로 환산해 합친 "전체 계획 합산" 카드(기간 슬라이더 포함)를 바로 볼 수 있음
- **실제 매매 이력 반영**: 보유종목은 등록 시점 수량/평단가만 저장되는데, 그 뒤 '매매 이력'에 기록한 추가 매수/매도는 자동으로 반영되지 않는 구조였음(`Holding`을 수정하는 기능이 없어서) — `domain/position.ts`의 `deriveCurrentPosition`이 가중평균 원가법으로 "등록 시점 값 + 그동안의 매매 기록"을 다시 계산해서 진짜 현재 수량/평단가/투입원금을 구하고, 보유종목·종목상세·적립식 계획·포트폴리오 합산·배당·자산 스냅샷까지 전부 이 값을 기준으로 삼음. 예전엔 이미 진행 중이던 적립식 매수의 과거 이력이 시뮬레이션에 반영되지 않던 문제였음
- **포트폴리오 합산 시뮬레이션**: 전 종목 복리 기대수익을 기간/금액/가정수익률 슬라이더로 조정하는 what-if, "세후 보기" 토글로 국내/해외 세율 자동 적용
- **세금/수수료 계산**: 국내 매매차익 비과세, 해외 양도소득세(기본공제 포함), 배당소득세, 환전수수료 — 모두 UI에서 가정값 조정 가능하도록 설계 (`src/renderer/src/domain/tax.ts`)
- **배당 관리**: 배당 기록 입력 + 세후 배당 계산 + **주/월/년별 배당 수익 막대그래프** (최근 12개 구간)
- **매매 이력**: 매수뿐 아니라 **매도**도 기록 가능, 종목별 요약은 순매수 기준으로 집계
- **캘린더**: 매수·매도·배당 지급일 + 적립식 계획의 예정 회차를 한 달력에서 확인. 날짜를 클릭하면 그날의 내역이 아래 목록에 표시됨
- **자산 증식 그래프 — 과거 시세로 평가금액 소급 계산**: 보유종목 등록일 + 매수/매도 기록으로 계산되는 누적 투입원금(실제 히스토리), 앱을 열 때마다 하루 1번씩 기록되는 평가금액 스냅샷(오늘부터, 실시간가 기준)에 더해서, **실제 과거 시세 기반 평가금액**을 종목별로 "그 날짜에 몇 주를 들고 있었는가"(매매 이력) × "그 날짜의 실제 종가"로 복원해서 등록일까지 소급해서 보여줌(`domain/historicalValuation.ts`). 국내 종목은 상장일까지 정확한 일별 종가를 구할 수 있고, 해외 종목은 조회 가능한 과거 범위가 최대 약 9년(그보다 먼 과거는 그 종목만 제외되고 안내 문구가 뜸)으로 제한적임. 통화가 섞이면 더할 수 없어(환율 미지원) KRW/USD를 각각 별도 카드로 표시
- **배당 자동 계산**: 배당 기록을 직접 입력하지 않아도, 지금 보유 중인 종목의 최근 결산 기준 실제 주당배당금·배당수익률(네이버 금융 공개 데이터, `naverClient.getDividendInfo`)을 자동 조회해서 현재 보유수량 기준 예상 연간 배당금을 계산해 보여줌. 배당수익률은 네이버가 보여주는 반올림된 값(소수점 1자리인 경우가 많음) 대신, 주당배당금 ÷ 현재가를 직접 계산한 정밀한 값을 우선 사용함(`preciseDividendYieldPercent`). 적립식 계획에서도 "자동 조회" 버튼으로 가정 배당수익률을 직접 채울 수 있음 — 실제 지급일별 정확한 배당 이력까지는 공개 데이터로 재구성할 수 없어서(최근 결산 수치만 제공됨), "실제로 받은 배당"은 여전히 아래 표에 직접 기록해야 정확히 남음
- **관심종목 / 보유종목 실시간성**: 종목 검색/추가, 시세 자동 갱신(장 시간에 맞춰서만 폴링), 갱신될 때마다 가격 셀이 깜빡이는 효과, 국내/미국 장 상태 배지, 종목 아바타(로고 대신 티커 기반 고유 색상 배지)
- **종목 상세 페이지**: 보유 종목 목록에서 종목을 클릭하면 그 종목만의 실시간 시세(자동 갱신 포함), 누적 투입원금·보유수량 추이, 과거 배당 내역을 모아서 봄. 관심종목에서 클릭해도 연결됨 — 같은 티커의 보유종목이 있으면 이 풍부한 화면으로, 없으면 실시간 시세만 보여주는 가벼운 화면으로 자동 분기. 실제 주가 차트(캔들)는 과거 시세 API를 쓰지 않아 제공하지 않음. **종목 관련 정보**도 함께 보여줌 — 관련 뉴스(네이버 금융, 클릭하면 기본 브라우저로 열림), 배당 자동 조회(위 항목과 동일한 데이터를 이 종목 기준으로), ETF라면 운용사·총보수·배당수익률(TTM)·NAV 괴리율·기간별 수익률 요약(국내 ETF만 세부 지표 제공, 해외 ETF는 "ETF다"라는 사실만 확인됨) — 다만 **구성종목별 정확한 보유 비중은 안정적인 공개 API를 찾지 못해 제공하지 않음**(정직하게 밝혀둠)
- **증권사 API 연동 (토스증권 Open API)**: 시세(Market Data) 조회만 사용 — 계좌 조회/주문 채널은 의도적으로 만들지 않음. `API 연결` 탭에서 클라이언트 자격증명 저장 및 연결 테스트 가능

### 시세 자동 갱신 & 장 시간 인식

관심종목/보유종목 페이지에서 "자동 갱신"을 켜면 15초~5분 간격으로 시세를 다시 불러옵니다. 이때 종목 통화(KRW/USD)로 국내(KRX)·미국 증시 중 어느 시장인지 판단해서, **정규장은 물론 장전·장후 시간외까지 포함해 해당 시장이 열려 있을 때만** 실제로 API를 호출합니다(`src/renderer/src/domain/marketHours.ts`). 장이 전부 닫혀 있으면 자동 갱신은 대기 상태로 표시되고, 자격증명 오류 등으로 3회 연속 실패하면 스스로 꺼집니다. 수동 "현재가 새로고침" 버튼은 이 제약과 무관하게 항상 즉시 조회됩니다.

두 페이지가 거의 같은 폴링 로직을 반복하지 않도록 `useAutoRefreshQuotes` 훅으로 공유합니다. 회사 로고는 쓰지 않습니다 — 종목 수가 많고 CSP가 외부 이미지도 막고 있어서, 대신 티커를 해시한 고유 색상 배지(`StockAvatar`)로 가볍게 대체했습니다.

지수/환율/과거 시세/배당 정보(`src/main/marketData/naverClient.ts`)는 전부 네이버 금융의 비공식 공개 엔드포인트를 쓰기 때문에 로그인·API 키가 필요 없지만, 네이버가 응답 구조를 바꾸면 깨질 수 있습니다 — 그럴 땐 이 파일만 고치면 되도록 파싱을 여기 안에 가둬뒀습니다. 해외 종목은 티커만으로 바로 조회가 안 되고 네이버 내부 코드(예: AAPL → AAPL.O)가 필요해서 자동완성 검색(`resolveForeignSymbol`)으로 먼저 알아낸 뒤 조회합니다. 원화 환산도 어디까지나 화면 표시용 추정치이고, 보유종목 데이터 자체(평단가 등)는 항상 원래 입력한 통화 그대로 저장됩니다.

다음 단계 후보: electron-builder를 통한 배포 패키징, 캘린더 알림/리마인더, (기능이 더 늘어나면) 페이지별로 흩어진 시세 폴링을 하나의 공유 스토어로 합치는 리팩터링.
